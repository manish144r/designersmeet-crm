# AIDER HANDOFF — DesignersMeet CRM (V2, 2026-05-19)

Full FE+BE rebuild from the locked brief. Aider takes it from here for
feature/data work. The brief and the design system are **locked** — four
enforcement layers will fail your PR if you touch them without `[brand-change]`.

## What is built (do not redo)

- **Design lock** (4 layers) — `brief/DESIGN-LOCK.md`. Tokens generated by
  Style Dictionary from `brief/tokens.json`. `npm run lint` fails on any raw
  hex/rgb/hsl.
- **Frontend** — 15 pages (+ spec sheet) translated 1:1 from
  `brief/mockups/*.html` by Codex into `packages/frontend/src/pages/<slug>.tsx`.
  Router in `src/App.tsx`. shadcn-style primitives in `src/components/ui/`.
  Auth in `src/auth/AuthProvider.tsx` (MSAL config preserved; Google/Apple;
  `VITE_DEMO_MODE` bypasses all three).
- **Backend** — Express + knex CRM API in `packages/backend/src/crm/`.
  14 resources, CRUD + pagination + filter, MSAL/Entra JWT middleware
  (dev bypass), zod validation. Migrations in `src/crm/migrations/`.
- **FE↔BE infra** — TanStack Query hooks (`src/hooks/useResource.ts`),
  Zustand UI store (`src/stores/uiStore.ts`), demo fixtures
  (`src/lib/demoData.ts`). Integration stubs in
  `packages/backend/src/integrations/{m365,shopify,meta,email,stripe}/`.

## Aider CAN modify

- `packages/frontend/src/hooks/**`
- `packages/frontend/src/stores/**`
- `packages/backend/src/services/**` (create as needed)
- `packages/backend/src/integrations/<name>/**` (fill in the stubs with real
  transport — Graph, Shopify GraphQL, Meta, ESPs, Stripe)
- `packages/*/tests/**`, `packages/*/src/**/__tests__/**`
- `packages/backend/src/crm/migrations/**` (new migrations only; never edit a
  shipped one)

Primary near-term work: **bind each page to live data**. The pages are
faithful static translations; wire them to `useList`/`useItem`/`useCreate`
from `src/hooks/useResource.ts`, replacing hardcoded mockup rows. Then fill
the integration adapters per `brief/spec.md` §8.

## Aider CANNOT modify (commit will be rejected)

- `brief/**` (mockups, tokens.json/.css, spec.md, screenshots, generators)
- `packages/frontend/src/pages/**` (Codex-owned fidelity output)
- `packages/frontend/tailwind.config.ts`, `tailwind.tokens.ts`
- `packages/frontend/src/styles/tokens.css`
- `packages/frontend/src/components/ui/**` (shadcn primitives)
- `packages/frontend/eslint.config.js`

To change any of the above: edit `brief/tokens.json` (or a mockup),
`npm run tokens`, refresh visual baselines, commit with `[brand-change]`.

## Gates every PR must pass

1. `cd packages/frontend && npm run lint` — ESLint `dm/no-raw-color` + CSS guard.
2. `cd packages/frontend && npm run build` — tsc + vite.
3. `cd packages/backend && npm test` — vitest CRM suite (10 tests).
4. Visual regression — `tests/visual-regression.spec.ts` ≤2% per page,
   ≤0.5% on primary CTA / sidebar / logo (when Storybook+Playwright wired).
5. Commit-msg + pre-commit hooks (activate: `git config --worktree
   core.hooksPath .husky`).

## Known gaps for Aider

- Pages are static (mockup-faithful); not yet wired to `useResource` hooks.
- Integration adapters are typed stubs (return canned data) — need real
  transport + auth token plumbing from `req.user` (Entra delegated token).
- SSO buttons on `01-signin` are visual; wire to `AuthProvider.signIn(...)`.
- `npm run migrate` only needed for `DATA_PROVIDER=sqlserver` (prod); dev runs
  the in-memory store.
- Old freelancer-domain files remain on disk (unused, not imported) — safe to
  delete in a dedicated cleanup PR if desired.
